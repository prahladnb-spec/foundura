# Foundura: notes for working in this repo

- Monorepo: pnpm + Turborepo. Build `@foundura/shared` before the apps (`pnpm --filter @foundura/shared build`).
- API: NestJS 11 + Drizzle (not Prisma). Schema in `apps/api/src/db/schema.ts`; after changing it run `pnpm --filter @foundura/api db:generate` and commit the new SQL in `apps/api/drizzle/`.
- Use explicit `@Inject(...)` in Nest constructors; tests run through Vitest with SWC.
- Validate request bodies with the shared zod schemas via `parseBody`.
- Scheme rules are JSON `Condition` trees from `@foundura/shared`. Never add a fact the scan doesn't collect; `test/schemes-seed.test.ts` enforces this. New schemes ship with `last_verified_at = null` until an editor checks the official source. Scheme Hindi lives in `schemes.translations.hi` with a fingerprint of the English; never serve a translation whose fingerprint doesn't match (use `localizeScheme`).
- Privacy rules: don't store anonymous scan answers, don't expose turnover/funding/shareholding publicly, record consent changes as new ledger rows, and keep `/me/export` and `DELETE /me` complete when adding tables with personal data. Usage counts are daily totals in `daily_counts` (metrics listed in `@foundura/shared` `METRICS`); never attach a user, IP or cookie to them.
- Saved scan results live only in the link's `#` fragment (`scan-form.tsx` `HASH_KEYS`), which browsers never send to a server; never move them into the query string or a request.
- The platform never handles money.
- Founder document templates live in `apps/web/src/documents/` as structured blocks; the Word/Excel/PowerPoint files are generated from them, so never commit binary templates. Legal instruments set `lawyer: true`; finance documents are matched by `checkWith()` for a CA notice. Never claim a professional review in copy: `REVIEWS` in `documents/index.ts` is the only place, and only after a real review. When you change a legal point, update `CHECKED_ON` and keep the guide and template consistent. Guides and templates are English; titles and summaries also need every interface language (Hindi on the template, the rest in `documents/translations.ts`). Spreadsheets that are plain tables use the `grid` builder; Hindi or example versions go in `variants.ts`. Glossary terms live in `apps/web/src/glossary.ts` (English and Hindi) and `glossary-translations.ts` (the other languages).
- Events: each has a `type`; the calendar filters by `EVENT_KINDS` in `@foundura/shared` (labels `events.kinds`), where `Challenge` is an open innovation challenge with a deadline. Public endpoints only return `published` events; imported events come from `event_sources` through `EventSyncService` (iCalendar or schema.org JSON-LD) and must be fetched with `safeFetchText`, which blocks private networks. `EVENT_SYNC_ALLOW_PRIVATE` is for tests only.
- Web copy: sentence case, plain words, no all-caps labels. Interface text goes in `apps/web/src/i18n/<lang>.ts`, all the same shape as `en.ts`; email text (English and Hindi only) in `apps/api/src/mail/templates.ts`, written as plain text; `mail/html.ts` builds the branded HTML version from it (blank lines, "- " lists, "--" small print) with the logo attached inline, so emails load nothing from the web. Design tokens live in `apps/web/src/app/globals.css`.
- Languages: `LANGS` in `apps/web/src/i18n/config.ts` (en, hi; Indian mr, kn, ta, te, gu, bn, ml; foreign es, de, fr, pt (Brazil), ar, he, ja). English is at plain URLs, others under `/<code>`; build links with `lp()`. Each language has a `LANG_INFO` entry (tag, `dir`, `script` regex for non-Latin scripts, `wideNav` when long menu labels need the compact menu until 2xl screens), plus `INTL_LOCALE` and `MONTHS`. Client components get text from `useT()` (the root layout's `I18nProvider`) and helpers from `i18n/util` and `lib/labels-core`; never import `@/i18n` or `lib/labels` in client code (server-only, so other languages stay out of the browser). Template titles, glossary terms and page SEO for es/de/ar/he are in `documents/translations.ts`, `glossary-translations.ts` and `seo-intl.ts`; every later language keeps all three in one file, `i18n/content/<code>.ts`, registered in `i18n/content/index.ts`. Fonts: Indian scripts use the regular-width Anek family (`@fontsource-variable/anek-*`), Marathi reuses Devanagari, Japanese uses system fonts (a kanji web font would break the weight budget) with `word-break: auto-phrase` on headings. Guides, the MedTech guide, legal pages, scheme details and emails exist only in English and Hindi: other languages show the English marked `lang="en"` with a translated note (`contentLang()`). Every language except Hindi was drafted by Claude and carries an "unreviewed" note until a native speaker checks it; record that only in `TRANSLATION_REVIEWS` (`i18n/reviews.ts`) after a real review. Arabic and Hebrew are right to left: use start/end utilities (`ms-`, `ps-`, `start-`, `text-start`, `border-s`), never left/right; maps stay `dir="ltr"`. `e2e/tests/languages.spec.ts` checks every language (untranslated text, popular searches that find results, the header fitting at laptop widths), and `weight.spec.ts` has a budget per language.
- Brand: the Foundura logo (navy #003271, orange #FE8202) lives in `apps/web/public/brand/` as SVG: `foundura-logo.svg` (mark + wordmark, 3602 × 1000), `foundura-logo-white.svg` for dark backgrounds, `foundura-mark.svg` (F with rocket), plus `foundura-logo-email.png`. Every logo includes the rocket, the browser icons too: `app/icon.svg` is the mark with its navy turning white in dark mode, `favicon.ico` puts it on a white rounded tile, `apple-icon.png` on white. The tagline is text (`chrome.tagline`, every language), never part of the image. Share images (`lib/og.tsx`) embed the logo; main pages get the default `[lang]/opengraph-image.tsx` through `seoMetadata`, and detail pages with their own image pass `ownImage: true`.
- Visuals ("paperwork made friendly"): illustrations are hand-drawn SVGs in `apps/web/public/art/` (ink #141b47, marigold, manila #e8cf8f, red tape #c94a36, fills offset a few px from outlines, no words so they suit both languages, always `alt=""`), placed with `Art`/`PageIntro` from `components/art.tsx`. Icons are lucide via `components/icons.tsx` (`Icon`, `CategoryStamp` postage stamps, `Monogram`, `KindIcon`, `FormatIcon`); keep icons beside text `aria-hidden`. Template covers are SVGs in `public/art/covers/<slug>.svg` (tinted by file type: marigold PowerPoint, green Excel, indigo Word), listed in `documents/covers.ts`; a covered template shows on the templates page shelf, beside its title and on its share image. Infographics live in `components/infographics/` and are real lists or tables with text in `en.ts`/`hi.ts`. Motion: at most one moment per page, only inside `prefers-reduced-motion: no-preference`. India is shown as a tile map, never a drawn outline map (official Survey of India boundaries would be required).
- SEO: every main page has an entry in `apps/web/src/seo.ts` (English and Hindi): focus keyphrase, SEO title ≤60 characters starting with the keyphrase, meta description 120–160 characters containing it, excerpt ≤50 words, exactly 15 keywords, slug. Use `pageMetadata(key, lang)`; detail pages build theirs with `seoMetadata`, `seoTitle`, `describe` and `keywordList`. Every page sets a canonical URL and en-IN/hi-IN/x-default alternates. Guides store their own SEO fields, checked live in the editor by `seoChecks` from `@foundura/shared`. `e2e/tests/seo.spec.ts` enforces all of this.
- Pages are checked by `e2e/tests/a11y.spec.ts` (axe, WCAG 2.1 AA) and `e2e/tests/weight.spec.ts` (page weight budget); keep heavy content out of client components. Hindi and Marathi fonts (bold heading cuts and unhinted Mukta Devanagari) are made by `apps/web/scripts/build-display-font.py` into `src/fonts/`; each language preloads only its own first fonts (`src/app/font-urls.tsx`), so add an entry there for a new language.
- Funding directory (`/funding`): entries live in `apps/web/src/funding/directory.ts` (organisations and public programmes only, never individual investors), grouped by state code or region and drawn on the India tile map. Entry text is English, marked `lang="en"` on other languages; interface text is `funding` in each dictionary. Set `CHECKED_ON` only after an editor has opened every link and confirmed the figures; until then the page says the list is unchecked. Add `url` only for an official site you know is right, and `scheme` when the programme is also a Foundura scheme. Each entry has a "Report a change" email link; corrections come by email so the site stores nothing.
- Funding basics (`/basics`): an eleven-chapter course in `apps/web/src/basics/` (`text-en.ts` and `text-hi.ts` hold the same facts; `chapters.ts` adds glossary terms, templates and links). Other languages show the English with a translated note. Interface text is `basics` in each dictionary; the dilution calculator (`components/dilution-calc.tsx`) carries only arithmetic. Each chapter ends with three questions (`basics/quiz.ts`, English and Hindi, checked in the browser, nothing stored); when a chapter changes, check its questions. When an Indian rule changes, update both languages and `CHECKED_ON`. It is general information: keep the disclaimer and never present it as advice.
- Weekly email without an account (`newsletter_subscribers`, `digest/newsletter.service.ts`): double opt-in from the footer form; the confirm and stop pages need a button press, so mail scanners can't act. Unconfirmed sign-ups are deleted after 7 days and unsubscribing deletes the row. It goes out with the scheme alerts on Mondays and is part of `/me/export` and `DELETE /me` for the same address.
- About (`/about`) and contact (`/contact`) pages read who runs Foundura and the grievance officer from `legalDetails()`; never invent people or reply times. The 8 stages of the startup life cycle are the `/learn` journey infographic and the first basics chapter; keep both in step.
- States (`/states`, `/states/[code]` with lower-case codes from `TILES`): each page combines state schemes from the API, the funding directory, the support directory (`apps/web/src/support/directory.ts`: incubators, government startup hubs and mentoring networks; organisations only, unchecked until an editor sets `CHECKED_ON`) and public startups, with DPIIT's States' Startup Ranking (`states/ranking.ts`; update it when a new edition comes out).
- Perks (`/perks`, `apps/web/src/perks/directory.ts`): free credits, discounts and DPIIT benefits from the official programmes; no amounts (they go stale), no paid listings, no click tracking, "Report a change" by email. Unchecked until an editor sets `CHECKED_ON`. Entries are English; interface text is `perks`.
- Founder tools on "My startup": the progress tracker (`components/journey-tracker.tsx`; stages and step ids are `JOURNEY` in `@foundura/shared`, labels `progress.steps` in every dictionary, links in `apps/web/src/progress.ts`; saved as `journey_stage`/`journey_done` on the startup) and the private profile link (`profile_shares`, `startups/shares.service.ts`, page `/shared/[token]`): only a SHA-256 of the key is stored, one link per startup, it shows public profile fields plus the readiness score and progress if chosen, never figures, and it must stay out of usage counts, referrers and search indexes. Both are in `/me/export` and go with `DELETE /me`.
- Investor update builder (`/investor-update`, `components/investor-update-builder.tsx`): runs in the browser, sends and stores nothing, plain arithmetic only (runway = cash ÷ net burn). Interface and email text are `update` in each dictionary.
- Installable app: `api/manifest/[lang]` serves a manifest per language (start URL, shortcuts from the dictionary); icons in `public/icons/` are made from `foundura-mark.svg` (rocket included). No service worker.
- Guides (`/learn`): articles in the API, English only (other languages show them marked `lang="en"`). Each has a `topic` (`GUIDE_TOPICS` in `@foundura/shared`, labels `learn.topics`) and an optional guest author (`authorName`/`authorRole`/`authorUrl`), saved only when the editor confirms the author agreed (`author_consent_at`, never served). "Start here" is `START_HERE` in `apps/web/src/guides.ts`; "Most read" is `/articles/popular`, built from the anonymous daily page-view totals. Seeded guides live in `apps/api/db/seed-data/` and must pass `seoChecks` (`test/articles-seed.test.ts`). Every guide page ends with the general-information disclaimer; never promise a publishing schedule.
- Software and SaaS guide (`/sectors/software`, `apps/web/src/sectors/software.ts`, English and Hindi like the MedTech guide). When GST, export, payment or data protection rules change, update both languages and `CHECKED_ON`.
- Open data (`/data`, files at `/data/<id>.csv|json` from `apps/web/src/data/datasets.ts`, CC BY 4.0): schemes, the funding, support and perks directories, events and public startups (factual fields only, never figures or founder-written text). Never add anything personal; unchecked directories say so in the file.
- Foundura in numbers (`/numbers`): totals from the API lists and `/stats/usage` (30-day sums of a few METRICS). Totals only, never anything per person.
- Cities (`/cities`, `/cities/[city]`; `CITIES` in `@foundura/shared`, names and matching in `apps/web/src/cities/directory.ts`): support and funders matched on their English `base` text, events on their city, startups by the optional `city` on their profile. Support directory kind `corporate` holds company-run startup programmes, `coworking` workspace schemes, `campus` student and college programmes.
- Founder guides (`/mentors`, `/coworking`, `/students`, `/women`, `/selling`, `/global`, `/labs`, `/patents`, `/closing`): one component (`components/founder-guide.tsx`) with text in `apps/web/src/founders/guides.ts` (English and Hindi; other languages show the English). Each lists support directory entries: `kind: "mentoring"`, entries with a `desks` workspace offer, `kind: "campus"` or `for: ["students"]`, `for: ["women"]`, `kind: "corporate"`, `for: ["global"]` and `kind: "lab"` (public labs, testing and certification bodies, prototyping centres); the patents and closing guides have no list. The patents guide adds filing abroad, a deadline timeline and patent offices from `founders/patents.ts`; it says it hasn't been reviewed by a patent agent until one has checked it. Organisations only, never individual mentors, no paid listings. When a procurement, scheme or campus rule changes, update both languages and `CHECKED_ON`.
- Embeddable lists (`/embed/schemes|events|support?state=XX`, `embed.js` `data-widget`): chrome-free, nothing stored; text is `partners.embed*`.
- Site search: `/search` ranks in memory on the web server (`SearchIndex` in `@foundura/shared`, entries built in `apps/web/src/search/catalogue.ts`); add new content types there. Each entry holds both languages. Search pages are `noindex`, and only the outcome (`search` metric: found or none) is counted, never the query.
- Deployment (`DEPLOY.md`): one DigitalOcean Droplet with Postgres on it (`docker-compose.selfdb.yml`), started and updated with `deploy/up.sh`. The server never builds: CI publishes `ghcr.io/prahladnb-spec/foundura-api|web` on pushes to `main`, and `docker-compose.build.yml` is the build override. Email goes through ZeptoMail (`ZEPTOMAIL_TOKEN`, India host). If a provider changes, update both privacy pages and `PRIVACY_NOTICE_VERSION`.
- Security notes (headers, rate limits, dependency overrides, `patchSchema` for PATCH bodies) are in `docs/security.md`; update it when you change any of them.
- Tests: `pnpm test` (needs Postgres; e2e uses `TEST_DATABASE_URL`, default `foundura_test`). Browser tests: `pnpm build && pnpm e2e` (Playwright, in `e2e/`, fresh `foundura_e2e` database). When you change a page or flow, update its spec; new interface text on Hindi pages must pass the untranslated-English check in `e2e/tests/hindi.spec.ts`.
